## 0. 一句话结论

**改的不是原则，是"靠什么强制执行"的那一半。**

宪法 42 条里，28 条与交付形态无关（权威层级、Determination 三态、纯函数规则、双时点、事件追加、可复算、违约门禁的思想），原样保留；真正必须动的是**六条实质条款**——它们把"谁能说最终话"寄托在 PostgreSQL、四个数据库角色、常驻服务和仓库 CI 上，而这些在插件形态下要么不存在，要么换了载体。

同域里已经有两套按插件形态运行、可直接核对的先例（`deepseek-harness` 的 `packages/patent/*` 插件族、`dsh-patent-workbench`），所以这次修正不是设想，而是**让宪法追上已经存在的物理条件**。

## 1. 判定尺子：为什么有些条款必须改

对每一条逐一问三个问题，任一答案为"否"就是必须改的条款：

| # | 问题 | 答"否"的后果 |
|---|---|---|
| Q1 | 这条的**检验**在插件形态下还能跑吗？ | 检验跑不了 = 条款失去强制力，沦为口号 |
| Q2 | 这条假定的**执行者**还存在吗？（PostgreSQL / DB 角色 / 常驻服务 / 仓库 CI） | 执行者不存在 = 违法成本为零 |
| Q3 | 这条假定的**攻击面**还是同一个吗？ | 攻击面变了 = 防错了对象（例：现在要防"模型用 bash 直接改库"） |

按此尺子得到的分级：

| 分级 | 条数 | 条款 |
|---|---|---|
| 原样保留 | 28 | 3、4、5、6、7、8、10、11、11-1、11-2、12、13、13-1、14、21、22、23、24、27、28、29、30、31、33、34、35、36、37 |
| 措辞 / 机制微调 | 5 | 1、9、15、16、19 |
| **实质改写** | 6 | **2、18、20、25、26、32** |
| 补款 | 3 | 6-1（案号与申请号）、11-3（提醒送达不保证）、17（事实不得引用派生代理键） |
| 新增 | 5 | 2-1、12-1、13-2、20-1、38 |

## 2. 四处已核实的冲突（先修哪一边，是这次修正的核心选择题）

以下不是假设，是按插件形态实跑/读契约可核对的：

| # | 宪法要求 | 插件侧现状（证据） | 处置 |
|---|---|---|---|
| C1 | 第 3 条 / 11-1：`delivery_method` 缺失必须 `UNDETERMINED`，禁止默认送达方式 | `patent-deadline` 的库 API：**省略送达方式即按电子送达**（README「an omitted mode means electronic delivery」） | **修代码**。这正是第 3 条点名的三个危险默认值之一。允许的替代：把"案卷默认送达方式"做成一条**经人工确认的事实**，而不是函数的 `default` |
| C2 | 第 3 条：事实缺失 → `UNDETERMINED`，不得返回具体值 | 假日表未覆盖某年时，返回**不顺延的届满日** + `calendarCaveat: "2027"`（README「not assumed to be a working day」） | **修宪法**（新增 12-1）。基础值完全可确定，缺口只影响"顺延"这一层精化，属正当的降级而非兜底 |
| C3 | 第 2 条：禁止"以本地文件保存业务状态并作为读取依据" | 案卷事件日志 `_matter-log.md` 是**案件级唯一事实源**，`case.db` 只是只读投影（集成设计 §1、patent-matter 技能） | **修宪法**（改写第 2 条 + 新增 2-1）。文件日志与"影子 JSONL"的差别是可操作的（见 2-1 的四条判据） |
| C4 | 第 18 条：`app_core` / `rule_svc` / `llm_gateway` / `migrator` 四角色；第 26 条：跨客户检索禁止 | 无 PostgreSQL、无 DB 角色；单机单用户、数据在 `$DSH_HOME`（SQLite） | **改宪法**。角色模型失去执行者，用"能力面"替代；"跨客户"收窄为"本机多客户" |

另有 3 处"宪法已经写对、插件已经落地"的正例，说明冲突是局部的、不是整体的：

- 第 10 条（法源证据链 / `UNVERIFIED` 不进判定）→ `patent-law` 的 `law_verify`：未核验条号**绝不**报告为已核对。
- 第 12 条（禁止规则绕过）→ workbench 对期限引擎**软探测**，引擎缺失时"明确降级、不自行推算"。
- 第 21 条（可卸载）→ workbench 注释："绝不进 `inject`：否则未装 DSH Patent 的机器上整个工作台会 pending"。

## 3. 实质改写（替换条文）

### 3.1 序言 命题 2

> **原**：组合只在外围发生，绝不下沉到核心。Cordis 负责让能力可插拔……
>
> **改**：**组合只由宿主发生，绝不下沉到核心。** DSH（Cordis 宿主）负责让能力可插拔、可替换、可卸载；领域层不得引用宿主 API（`ctx.*`、插件清单、工具注册表、会话、提示词、配置），也不得假定自己运行在某个特定宿主版本上。一旦领域逻辑认识宿主，宿主就成了地基而不是外壳。

### 3.2 第 1 条（权威层级）—— 两处微调

- L4 的定义由「Cordis 插件、UI、集成、报表、通知」改为「**宿主与相邻插件**、DSH 插件、UI、集成、报表、通知」。
- 新增一行判据：**L5 的能力上限 = 插件暴露的工具面。** 模型能做什么，由工具签名定义；提示词里的禁止不算约束。

### 3.3 第 2 条 唯一事实源（重写）

> **事实只住在登记过的载体里。** 允许的载体只有三类，按类登记（见 2-1）：
>
> 1. **事务事实库**——嵌入式 SQLite（单机）或单库 PostgreSQL（服务部署）。承载主体、案卷、官文、送达、缴费、审计事件。
> 2. **案卷目录的追加式事件日志**（`<案卷>/_matter-log.md`）。承载案件级事件；唯一写入口是一个专用工具，不是编辑器。
> 3. **权威知识库**（判例/法规/指南索引、节假日表、价目表）。**只读**，永不写。
>
> 仍禁止的形态不变：以缓存、物化视图、搜索结果、前端存储作为写入依据或对外承诺依据；同一事实在两个载体里各存一份且无单一写入方。**业务时间不得由 `now()` 产生**（原第 2 条第二段原样保留）。
>
> **检验**：①删除全部派生层与缓存后重放事件得到一致状态；②删掉事务库后，案卷目录的日志仍能重建案件级**事件**事实（结构化事实仍归事务库，按 2-1 的分工）；③日志与库对同一事实同时主张时，视为违宪（不是"以库为准"，是登记错了）。

### 3.4 新增 第 2 条之一 载体登记与单一写入口

一个载体能被称作"事实源"，必须同时满足五条；缺一条，它只能是派生层或缓存：

1. **单一写入口**：写入只经过一个具名工具/用例，没有第二个写路径；
2. **只追加或单写入方**：要么 append-only（更正靠追加更正行），要么在同一时刻只有一个写入者；
3. **写入即校验**：每次写入可被机械校验（产物已存在、路径未被复用、取代链不分叉、一版只有一取代者、摘要哈希）；
4. **可备份可回滚**：备份与恢复是既定流程，不是临时操作；
5. **派生层不得回写**：投影方向单向，反向写入视为违宪。

**事实归属登记表是宪法附件**：每类事实（案卷身份、官文、送达、期限、费减资格、账单行……）必须且只能登记一个载体。新增一类事实，先登记后写入。

> **检验**：任取一行事实，能回答"它在哪个载体、谁写的、哪次写入"。回答不出即违宪。集成侧的双向投影（工作台改状态回写案件）出现一次即违宪。

### 3.5 第 18 条 权限即条款（重写为"能力面"）

数据库角色在单机插件形态下没有执行者（SQLite 无角色，宿主与用户同 OS 账户）。强制点改为五个面，**权限划分仍是宪法要求，不是运维优化**：

| 面 | 机制 | 谁能穿过 |
|---|---|---|
| 事实库 | 库文件位于**模型沙箱写域之外**（`$DSH_HOME/<plugin>/`），不在会话工作区内 | 仅插件宿主进程 |
| 工具面 | 模型只能经注册工具操作；工具入参是唯一写入口 | 模型（受 schema 限制） |
| 交互面 | 提交、确认、签发必须是**一次可留痕的人机交互**（返回草稿 → 用户确认 → 提交） | 人工账号 |
| 配置面 | `config` / patch / profile 由用户持有，插件不得自改；改动即事实（留痕） | 用户 |
| 旁路 | 审计链缺口检测 + 定期一致性自检（第 38 条） | 只用于**发现**绕过，不假装能阻止 |

**必须写明的一句**：沙箱是默认策略，不是保证——用户可提权到 full access。因此第 38 条的旁路自检是宪法要求，不是可选项。

> **检验**：以模型身份（通用文件/命令工具）写事实库必须失败；策略临时提权后写库成功，但下一次自检必须报出审计缺口并阻断对外输出。

### 3.6 第 20 条 插件契约（改写）＋ 新增 20-1

第 20 条保留原文的三条禁令，把"插件"落到 DSH 宿主：

> 插件只能通过**声明的服务接口**访问能力（`provide` / `inject`），不得 import 其他插件的内部实现，不得直接写非本域的表或文件。需要写业务数据时，必须调用本插件的用例层，由用例负责事务、校验、审计与规则调用。SQL 只允许出现在 `infra/` 内。

**新增 第 20 条之一 作用域、软探测与服务契约**

1. **作用域是一等概念。** preset 内挂载的插件与服务，与 profile 根域不互通；跨插件消费的能力必须在**共同作用域**显式注册为服务，不得靠工具注册表旁路（preset 内的工具注册表是隔离的）。
2. **可选依赖一律软探测，绝不进 `inject`。** 进了 `inject`，未安装该插件的机器会整块挂起——这是可用性事故，不是"严格依赖"。
3. **服务接口是公开契约。** 方法名、签名、语义的变更属破坏性变更，走第 16 条两段式；服务缺失时的降级行为必须写明，且**降级不得自行推算**（第 12 条）。

> **检验**：①卸掉专利内核插件族，工作台必须照常启动，期限看板显示"引擎不可用 + 手工录入"而不是空白或崩溃；②卸掉工作台，内核的全部工具与交付门禁照常工作；③服务签名变更未走两段式，CI 失败。

### 3.7 第 25 条 提案—提交（改写实现机制）

写路径的**形状**不变，载体换了：

```
读取（授权面） → 产出 proposal（草稿/候选/建议） → 人工确认（可留痕交互） → 规则校验 → 确定性代码提交
```

- proposal 与正式记录**分表/分文件**存放；proposal 允许脏、允许错、允许被丢弃。
- "人工审阅"必须是一次**可留痕的交互**（工具返回草稿 + 界面确认，或 `ask_user_question` 的结果落库），**不接受**"提示词里写了请确认"。
- 提交分支必须是确定性代码，**不得**由模型自由拼 SQL 或直接写文件。
- 正式表中由 LLM 起草的字段，仍须携带 `origin = 'llm'` 与人工确认者（第 24 条保留）。

> **检验**：①模型侧不存在任何能把未确认输入变成事实的工具；②每条正式记录都能追溯到一次确认交互的 id；③以"省略确认直接调用提交工具"的方式构造用例，必须被拒。

### 3.8 第 26 条 最小上下文（改写作"注入与可读面"）

作用对象从"我们投喂什么"变成"插件让模型看见什么、能读到什么"：

1. **算作上下文的**：插件注入的提示词段、自动召回、技能、工具返回值、附件。
2. **每次注入必须带 scope**（客户 / 案卷 / 任务），scope 记入注入日志；无 scope 的注入视为违宪（原条检验保留）。
3. **越 scope 读取必须在工具层拒绝**，不能只靠提示词劝阻——模型会照做提示词之外的合理请求。
4. **会话记忆、知识库召回、工作台共享记忆一律是 L5**：永不作为事实、永不作为判定依据、永不进入审计链。它们可以提示"去看哪个文件"，不能替代文件。

> **检验**：以另一个客户的案卷号调用任一工具，必须返回拒绝而非数据；关掉自动召回后，全部判定结果不变。

### 3.9 第 32 条 违宪门禁（10 项 → 11 项）

| # | 检查 | 对应条款 |
|---|---|---|
| 1 | 依赖方向白名单（domain 零宿主依赖：不 import cordis / `@deepseek-ai/*` / `ctx`） | 19 |
| 2 | `rules/` 外的日期/金额运算扫描 | 7 |
| 3 | 规则四项覆盖 + `UNVERIFIED` 规则未进生产路径 | 10、11 |
| 4 | **以模型身份写事实库必须失败**（沙箱写域断言，替代原"`llm_gateway` 写核心表失败"） | 18、25 |
| 5 | 本地库迁移：空库→最新、旧快照→最新，结构哈希一致；**升级前备份存在** | 16 |
| 6 | 派生层删除重建，**事实表内容哈希不变** | 17 |
| 7 | 最小插件集冒烟 + **无 LLM 端到端** | 21、28 |
| 8 | 派生结果 `rule_version` 非空 | 12 |
| 9 | 已发出账单 `UPDATE` / `DELETE` 必须失败 | 34 |
| 10 | 账单行可回溯至 `rule_version` 或 `price_list_version` | 35 |
| 11 | **工具删参测试**（13-2）+ **服务降级测试**（20-1） | 13-2、20-1 |

## 4. 新增条款（全文）

### 第 12 条之一 覆盖缺口声明（coverage caveat）

当**基础值**由完整事实算出、而缺口只影响某一层可选精化时，允许返回"值 + 缺口声明"，不得因此返回 `UNDETERMINED`，但必须同时满足：

1. 基础值不得含任何猜测（例：不顺延的届满日是精确的，假日表缺年不影响它）；
2. **同时返回未精化值与已精化值**，由调用方选择，不得只给一个；
3. 缺口必须**可机读、点名**（年份 / 法域 / 规则版本），进报告；
4. 缺口声明**不得**用于掩盖事实缺失——事实缺失仍是 `UNDETERMINED`（第 3 条）。

> **检验**：假日表只覆盖到 2026 年时，2027 年的届满日返回"不顺延日期 + `calendarCaveat: '2027'`"；同时**不得**返回"按 2026 年假日顺延"的猜测值。

### 第 13 条之二 工具入参不补事实

**工具入参与规则入参禁止用默认值补一个事实。** 省略即未知：返回 `UNDETERMINED` / 要求补参，不得按"最常见分支"处理。

点名禁止的形态：省略送达方式即按电子送达；省略判定时点即取系统当日；省略年度即取最近一年；省略法域即取 `CN`。

这与第 8 条（法域无默认值）、第 4 条（判定时点显式）是同一原则在工具面的延伸——**工具是模型最容易漏参的地方，也是默认值最容易被当成善意的地方。**

> **检验**：对每个工具做"删参测试"——把每个可选参数逐个删掉，输出必须是 `UNDETERMINED` / 拒绝 / 显式要求补参，不得是某个具体值。任一工具出现具体值即 CI 失败。

### 第 17 条（补款）事实不得引用派生物的代理键

派生层的记录可能被删除重建，其代理键（uuid）随之变化。因此：**任何事实表都不得用派生表的代理键做外键**，事实之间以业务键相连（案卷 + 义务 + 触发动作）。

> **检验**：`drop derived → rebuild` 后，事实表内容哈希不变（比第 17 条原有的"逐行一致"更强：事实一行都不能动）。

### 第 38 条 旁路与完整性自检

1. 事实库与事件日志必须能**互相重放校验**：日志 → 状态；库 → 日志缺行。
2. 启动时与每日至少一次自检，报四类缺口：日志缺行、库内事件无对应日志、取代链分叉、审计链断点。
3. 有缺口时：**阻断对外输出**（账单导出、通知书/交付件导出），不阻断内部查看。
4. 缺口只由人闭合（补录更正行，或恢复备份）。**模型不得"修复"缺口**——它分不清补录与伪造。

> **检验**：手工删掉日志末行 → 自检报缺口 → 导出被拒；模型尝试用工具补写该行 → 必须被拒或被标记为"未经确认"。

### 第 6 条之一（补款）案号与申请号是两种身份

原条以申请号为案卷唯一自然键。插件与文件形态下，案卷目录以**业务案号**命名，而申请号在建案时可能未知。故补：

**案卷有且只有两种身份，不得互相冒充**——业务案号（工作单元 / 目录名 / 作业对齐键，人类可读）与申请号（法律对齐键，一经取得不可改写）。法律义务只挂在申请号上；未取得申请号的案卷是"预备案卷"，不产生任何期限（原第 3 点保留）。二者的映射必须双向可查，首次绑定写入事件日志。

> **检验**：同一案号只能绑一个申请号；申请号不得被改写；预备案卷出现在期限台账中即违宪。

### 第 11 条之三（补款）提醒的送达不被保证

插件形态下宿主不运行就不会提醒。故补：**提醒是尽力而为的视图，义务台账的正确性不依赖任何通知被送达。** 用户离线期间不产生补偿性承诺；"已发提醒"不得作为免责证据。

> **检验**：停用全部提醒通道，逾期清单仍完整；任一期限结论不受提醒配置影响。
